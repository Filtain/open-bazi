# 八字解读与问答 SOP v0.2.0

本版采用一个明确的子平分析工作流，支持实质性的命格、喜忌和未来趋势解释。它不是“全流派唯一正确算法”，也不是经科学验证的事件预测器。历法计算、结构匹配、传统解释必须分别标识。

## 数据流

出生资料 → 历法引擎 → 结构事实和运年区间 → 命盘六节分析 → 大运与逐年分析 → 围绕同一报告追问。

- `engine.py`：原有确定性排盘。策略版本 `standard-23-minute-qiyun-v0.1`。
- `analysis.py`：结构证据包 `ziping-evidence-0.2.0`。不向模型委托干支、起运或时间分段计算。
- `sop.py`：12条版本化解释规则、固定章节、输出校验与提问年份提取。版本 `reading-sop-0.2.0`。
- `main.py`：两阶段生成、内存报告绑定、对话历史、供应商适配和本机访问边界。
- 网页：显示规则初读、实际生成阶段、四个报告入口、引用详情和聊天。模型文字全部通过 `textContent`/文本节点显示。

## 1. 排盘和规则初读

校验日期、时间和夏令时后产生四柱、阴阳五行、十神、藏干、起运与大运。原有算法和边界没有改动。

程序另外提取：

1. 月令本气及其十神。寅卯、巳午、申酉、亥子分别采用四时旺相休囚死表，仅提供季节参照；辰戌丑未保留杂气，不将全月硬编码为土司令。
2. 日主同五行藏干根，记录柱位与本气/非本气。不把印星当作同五行根，不用固定分值加总旺衰。
3. 年、月、时明干的印比生扶与食伤财官杀泄耗克；日干自己不重复计入。藏干证据仍完整保留。
4. 月令本气取格线索、月令藏干在年/月/时干透出。建禄采用十干禄位；阳刃只匹配甲卯、丙午、戊午、庚酉、壬子。其他只输出月令取格线索，不自动宣布成格。
5. 天干五合、地支六合、六冲、六害、相刑两支配对、辰午酉亥重复自刑、三合与三会齐支。保留具体柱位与重复位置，只匹配结构，不自动合化或抵消冲刑。没有全局刑冲优先级、六破、半合、拱局或神煞推导。

## 2. 命盘报告（第一次模型请求）

必须依次完成六节：

| 章节 | 固定检查点 |
| --- | --- |
| 命盘总论 | 日主、月令、四柱与主要结构 |
| 日主旺衰 | 月令、通根、印比与泄耗克；支持、反证、偏强/偏弱/难定的条件判断 |
| 命格与格局 | 月令取格与透出；建禄/阳刃等候选；成败配合和反证，不能把候选当成已成格 |
| 喜忌与用神 | 扶抑、格局、调候分别说明；证据不足保留备选，不按数量补缺 |
| 事业与财富主题 | 食伤表达、财资源交换、官杀责任、印比学习协作等传统象意，结合全盘，给现实行动 |
| 情感与相处方式 | 结构与相处主题、协作压力和可调整方式；不从单神断婚姻事件 |

R11提供常见格局的配合清单，R12提供普通格局下的条件性扶抑规则。规则是现代项目摘要，不能冒充古籍原文。从格、化气格、完整精细调候等例外尚未编码，不能声称程序已经判定。

每节须返回 `judgment`、`basis`、`conditions`、`advice`、`fact_ids`、`rule_ids`。服务端控制标题和章节顺序，检查全部必需章节、文本长度、引用存在性及每节必需证据。没有通过则返回错误，不展示为完成的报告。没有自动修复重试，避免追加费用。

## 3. 大运与流年（第二次模型请求）

第一步结果保存在本地内存，并作为条件性解释传入第二步：

- 八步大运逐段解释，提供干支、天干十神、藏干、与原局的位置关系和实际起止时间。过去大运可以说明阶段象意，但不编造已经发生的经历。
- 从所选年份开始解释五个流年；接近2099年时缩短。每年由当年立春至下一年立春划分。
- 按出生时刻、大运起止时刻切分流年。交运年会包含前后两段；边界左闭右开。程序同时提供流年与原局、流年与大运（含三者齐支）的结构关系。
- 出生前不作个人推演。尚未起运不能用首运替代。缺排运参数、大运覆盖不足都明确标记，不由模型补算。
- 给出年度主题、机会、挑战、条件与建议；最后形成未来重点总结。流年章节必须引用对应年份事实，不能引用别年的事实冒充当年。

第二步失败保留第一步；再次请求只续接第二步。已经完成的第二步再次提交直接返回既有结果。用户主动“重新生成总报告”才从第一步重来。

## 4. 固定问答流程

1. 绑定服务端报告ID，读取原始命盘与既有报告；请求不能注入新的事实、历史或系统提示。
2. 确认主题与时间。支持具体四位年份、范围如“2028到2030年”、今年/明年/后年/去年、未来一至十年。相对年份按服务端东八区当前年份解释，而非出生年份。
3. 程序重算提问对应的流年及大运分段，允许超出报告原本的五年窗口。无明确年份时沿用上一轮范围，首次提问附带原窗口；“那一年”等歧义应由助手澄清，不声称所有自然语言时间均能自动识别。
4. 连同原局、既有报告、最近8轮对话及固定规则发送给模型。既有报告是可修正的解释，不能当作已证明的事实。
5. 回答直接结论、具体依据、条件/反证、现实建议。必须引用R10及相关事实，解析到的流年陈述还要求对应年份引用。
6. 仅在结构与引用检查成功后追加历史。失败保留问题文本，不污染后续上下文。

问答暂不提供流月、流日、择日、合盘，也不根据聊天内容暗中修改出生资料。需要新命盘必须回到表单重新生成。

## 5. 可靠性与隐私边界

校验能证明“章节齐全、引用ID存在、必需证据被列出”，不能自动证明自然语言结论与证据一致，更不能证明传统预测有效。原局强弱、格局成败、喜忌仍需人工审阅。不同模型或重新生成可能给出不同的条件判断。

报告只在本地进程内存保存，最多8份、闲置6小时失效、每份20轮对话；无后台持久化和自动恢复。导出包含个人资料，应由用户自行保管。刷新页面不会恢复旧报告，重启服务清空记录与连接。

本版完整报告调用模型两次；单次追问调用一次。模型输出上限分别为6500、10000、3600 Token，实际费用和输出能力取决于供应商。生成超时或失败不自动重试；失败请求也可能由供应商计费。
